MS Thesis · Defense Brief

Reinforcement-Learning Correlation for Multi-Stage Attacks

A post-hoc, two-stage pipeline — a supervised identifier feeding a DQN correlator — evaluated honestly against an external, never-touched benchmark. The headline result is not a clean win, and that is the finding worth defending.

ScopeForensic correlation, not real-time detection
RL roleLink / don't-link decision only
External testDARPA2000 (LLDOS 1.0 & 2.0.2)
StatusStages 1–6 complete

§ Headline finding

Reported plainly, not reframed

On DARPA2000 — genuinely external data no training or tuning code ever read — the trained DQN does not outperform a naive rule-based baseline on pairwise link F1 (DQN 0.251 vs baseline 0.375), though it now leads on Adjusted Rand Index (0.081 vs 0.037) — the two headline metrics disagree, and both readings are reported rather than one picked to tell a cleaner story. The same DQN reached a mean validation F1 of 0.87–0.89 on CICIDS2017's held-out campaigns. That gap is a real, investigated cross-dataset generalization gap — exactly the failure mode a same-distribution validation split cannot reveal, and exactly why the external test set was insisted on in the first place.

Self-caught, not glossed over

A full-codebase correctness review (conducted after the headline numbers below had already been reported once) found three real bugs — the significant one: one of the DQN's 7 state features was silently constant for every DARPA2000 pair due to a vocabulary mismatch between the two datasets' label sets. All three were disclosed and fixed, Stage 4 was retrained from scratch, and Stage 5 was re-run — the numbers on this page are the corrected results, with the pre-fix numbers kept on disk rather than discarded. A follow-up pass then empirically tested the fix and the codebase's trickiest mechanism (the DQN's target-network sync) by running it directly rather than only re-reading it, and confirmed event IDs are genuinely unique across both datasets — verification depth documented in docs/stage6_limitations.md.

Implemented & evaluated

7-feature state built only from the identifier's predicted labels, never ground truth. First training run (5× false-negative penalty) converged to an near-"always link" policy; diagnosed, then re-run once with the penalty reduced to 2.5× — a disclosed, one-time adjustment, both runs reported.

External evaluation

Headline result

Full campaign reconstruction on all 316 DARPA2000 events, DQN vs a naive same-IP + 30-minute rule, identical clustering procedure for both so the comparison isolates the decision function.

The two metrics disagree: DQN leads on ARI (fewer, more purposeful clusters — one is 89% true-campaign members) but trails on pairwise F1 (baseline over-links, catching more true pairs by brute force at the cost of 26,063 false-positive pairs). Both readings are reported, not reconciled into one number. DQN still under-links relative to ground truth even in a zero-ambiguity case (LLDOS 2.0.2, no distractors at all).

3b

UNSW-NB15 cross-check

Optional, secondary

An independent Random Forest — same methodology as Stage 3, not a reuse of its actual model (no shared feature schema) — trained on UNSW-NB15's own canonical split. Headline: 68.0% accuracy, macro F1 0.481 — realistically more modest than CICIDS2017, as expected on a different, harder dataset. A documented UNSW-NB15 leakage concern (sttl/dttl, a simulation-configuration artifact) was tested with an actual before/after ablation rather than assumed — removing it changed accuracy by only +0.001, a result reported precisely because it complicates the tidier "found and fixed a leak" story.

§ Threats to validity

What to say when asked "but what about…"

DARPA2000's age

Predates web-layer attacks entirely. Used anyway because it remains the only source with genuine, dataset-native multi-stage campaign ground truth — CICIDS2017 required inventing a derivation heuristic for the same purpose (Stage 2 finding), which no newer flow dataset avoids needing.

Single environment, N=2 campaigns

The entire external headline rests on two campaigns from one simulated topology. Real, investigated result — not the same claim as generalizing to external intrusion data broadly.

No genuine web/WAF-tier data

CICIDS2017's "web" attack files are still flow-level captures, not HTTP-layer alerts. The planned DVWA + ModSecurity source was scoped, then deferred, then never built.

DARPA's identification signal is idealized

Stage 3's classifier cannot run on DARPA's schema at all — no equivalent flow-statistics features exist to compute. DARPA's own ground-truth labels stood in for "predicted" labels, an easier condition than CICIDS2017's training ever had.

Post-hoc scope, not real-time

Every design assumption is offline/batch — bounded episode windows, hour-long correlation windows. No throughput or latency claim was ever made or tested.
